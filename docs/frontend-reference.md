# NexRide reference refinement

The rider and driver workspaces retain Next.js App Router and the existing Supabase client, migrations, configuration and admin data operations. Reusable UI lives in `components/nexride`; `lib/nexride-i18n.ts` owns the English and Amharic strings. The rider experience uses light map surfaces and emerald actions. Driver screens use deep navy surfaces with the same controls and spacing.

## Preview boundaries

The previous public page used local state rather than authenticated booking, dispatch or payments. This implementation makes that boundary explicit on every screen. `/auth` signs existing accounts in through Supabase; preview profiles remain local sample profiles. The ride preview does not create accounts, match drivers, dispatch rides, send communications, charge money or produce live earnings. Preview state is versioned in `nexride-preview-v2`, and only contains a profile, preferences and sample trip. The old local account is migrated without its password and the old storage key is removed. Driver session state is temporary and preserved while navigating within the workspace.

- `lib/nexride-preview.ts`: replace `previewFare` with an authenticated fare adapter when that service is connected. Ride-card fares remain sample calculations and are separate from provider road distance/time.
- `components/nexride/rider-map.tsx`: rider home uses a geographic Leaflet map with OpenStreetMap raster tiles and visible attribution. `NEXT_PUBLIC_MAP_TILE_URL` can switch an OSM-compatible raster XYZ provider; include any additional provider attribution when changing it. Requests use normal browser caching and referrers, with no tile prefetch/offline download. Map load errors show a retry state while preview destination search remains available. No availability API is connected, so this map renders no vehicle markers.
- `lib/nexride-location.ts`: user-requested browser geolocation, or automatic restoration when permission was already granted. A finite geographic fix supplies the blue dot and accuracy circle in meters. Permission denial/revocation clears the dot; loading, timeout, unsupported geolocation and invalid fixes are recoverable. Coordinates remain in memory.
- `lib/nexride-home.ts`: Home/Work shortcuts and recent preview selections are versioned device data, not authenticated trip history. Nothing is pre-populated into history or saved shortcuts. Sample destination names are visibly labeled. Routing distances/ETAs are not invented.
- `components/nexride/map.tsx`: the other preview workflows keep an explicitly labeled route illustration without a fake user location dot. The OpenStreetMap link opens a real street map of Addis Ababa. It does not establish live dispatch.
- `components/nexride/destination.tsx` and `lib/nexride-journey.ts`: shared endpoints synchronize editable inputs, geographic pins and route review. No default pickup is assumed. Drags invalidate the previous route and require confirmation; reverse labels cannot change pin coordinates. Mobile uses a draggable, keyboard-resizable sheet and visual viewport sizing; desktop uses a side panel.
- `/api/rider/search` and `/api/rider/route`: server adapters for Mapbox v6 geocoding and driving directions. `MAPBOX_ACCESS_TOKEN` is preferred with legacy public-token fallback. No fallback geometry/duration is shown. Temporary provider results remain in memory; only labeled local preview places enter device history. Amharic catalog names match both scripts; provider results keep source names/addresses.
- `NEXRIDE_SERVICE_BOUNDS`: optional verified operational rectangle (west,south,east,north). Default bounds are explicitly labeled preview coverage. Invalid/unconfirmed endpoints, same locations, coverage violations and routing errors block continuation. Missing provider configuration allows only explicit preview ride options after valid endpoints.
- `components/nexride/ride-selection.tsx`: three vehicle illustrations and selectable Economy/Comfort/XL cards, a fixed payment/request footer, transparent pricing and a charge review dialog. Category capacity and fares are samples by default; pickup estimates are not synthesized. Disabled Request Ride plus a separate preview action preserve the booking boundary. Portrait uses a white bottom sheet; short landscape uses a map beside the panel so the list remains scrollable.
- `lib/nexride-booking.ts` / `lib/nexride-offers.ts`: strict quote validation, ETB totals including every supplied charge, revision/expiry handling, changed-price acknowledgement, bounded network waits and a synchronous request lock. Retry keys are stable for the same quote/category/payment. Pending navigation and map edits are locked; failed/uncertain responses are visible. Provider addresses and coordinates stay in memory.
- `/api/rider/fares`: sample calculations only, after validating geographic endpoints and coverage. `/api/rider/requests`: explicit 503 unconnected boundary, with no database trip/payment writes. The future server must authenticate, reprice and persist idempotency. No production dispatch integration is inferred from the existing taxi/delivery fare seeds.
- `components/nexride/rider.tsx`: matching, driver details, progress, rating and wallet are sample surfaces. Unconnected call, chat, sharing and payment actions display an availability dialog.
- `components/nexride/driver.tsx`: availability, requests, navigation and earnings are clearly labeled samples. Navigation graphics are not turn-by-turn instructions.
- `/admin`: existing Supabase authentication, role checks, realtime subscriptions and operations are preserved. Styling aligns with the navy/emerald system.

All dialogs use native modal focus containment, Escape handling and focus restoration. Controls meet the 44px target, forms use readable 16px inputs, safe area insets are respected, and reduced motion is supported. On rider home, CSS grid reserves separate space for the map, panel and navigation, including short landscape viewports. At 800px and below, a map and scrollable sheet fill the actual viewport; larger screens use a sidebar and map/panel workspace without device frames.

No licensed Benaiah font asset exists in the repository. An openly licensed Noto Sans Ethiopic fallback is bundled with the app, followed by system Ethiopic fonts. Its SIL Open Font License is included beside the assets. If a licensed font is added later, register it through `next/font/local` without fetching an unlicensed copy.

The rider splash uses a licensed high-resolution Addis Ababa photograph by DaneyWiki (CC BY-SA 4.0), with attribution next to the asset and on entry screens. The existing small city card image remains a crop from the supplied design reference and should be replaced if the reference’s image rights are unknown. The provisional folded-N splash symbol is separately named and documented under `public/brand/provisional`.

`lib/nexride-startup.ts` restores device preferences and the existing Supabase client session. It deduplicates initialization and bounds service waits at eight seconds without introducing a minimum splash delay. Session-based routing is a client UX decision; server and admin authorization continue to use their existing checks. Entry and splash messages use the shared English/Amharic translation system.

## Validation

`npm run build`, `npm run test`, and `npm run test:e2e`. End-to-end coverage exercises the rider preview, driver session continuity, language switching, profile migration without passwords, modal keyboard behavior, small-screen overflow, geographic position/accuracy and recenter, denied/unavailable/loading location, map failures, saved preview shortcuts, empty history, control/panel/navigation separation, destination selection, bilingual locality distinctions, route geometry/estimates, pickup dragging/confirmation, map selection, route retry/coverage guards, sheet resizing, ride-card selection, quote loading/retry, availability and charge guards, changed prices, request confirmation, duplicate submission protection, and admin authentication.
