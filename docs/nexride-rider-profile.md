# Rider profile and settings

The rider Profile screen follows the navy reference and uses the existing English/Amharic language context. It includes an account avatar (initials if unavailable), name, Rider label, edit action, My Rides, Payment methods, Safety Center, Help & Support and Settings. Privacy and sign-out sit below the main navigation.

Signed-in profile reads and updates use the existing Supabase `profiles` table and current user's ID. Updates contain only `full_name` and `phone`, verify the current authenticated user and require the updated row to be returned before showing success. Existing RLS remains authoritative. Email is read-only; contact-phone edits do not claim phone verification. No role, permission, verification or payment fields can be changed by this form. Auth changes clear the previously loaded profile. Failed saves retain the form for retry. Preview edits are labeled local and stored separately from the account.

Language and appearance affect the app and persist on this device. Profile keeps its navy presentation. The in-app trip-alert switch controls brief alerts when a previously observed booked trip changes server-reported state; essential trip status and safety remain visible. Push, SMS and email notification delivery are explicitly unavailable. Payment management, data export/deletion and support integration have explicit unavailable states rather than invented functionality. My Rides opens the existing history and receipts.

Sign-out uses Supabase's local-device scope, shows recoverable errors and resets preview/session startup state on exit. If the SDK clears the local session during a server failure, the screen explains that server sign-out is unconfirmed and offers a return to sign-in. It does not cancel bookings. Sign-out leaves non-account browser preferences and saved-place data; the privacy screen explains browser site-data clearing.

Validation: unit suite, TypeScript, production build, desktop/mobile Playwright coverage for profile validation, authenticated saves with recovery, read-only email, sign-out recovery, local preview persistence, menu dialogs, language/appearance and notification preferences. Authenticated browser tests use a mocked backend; actual project RLS requires authorized production fixtures to certify. No profile schema migration was needed. The separately documented rating concurrency migration remains pending access to the correct Supabase project.
